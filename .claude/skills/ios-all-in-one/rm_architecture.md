# Resource Module Architecture & Creating New Modules

## Resource Module Architecture (RM Pattern)

Every resource module in this collection follows the **Ansible Resource Module (RM)** pattern.
A resource module consists of **5 files** that work together:

### File 1: Module (`plugins/modules/ios_<resource>.py`)
- Contains `DOCUMENTATION`, `EXAMPLES`, `RETURN` docstrings
- Has a thin `main()` function that instantiates the config class and calls `execute_module()`
- The DOCUMENTATION must follow Ansible module documentation format

```python
# Minimal module main():
def main():
    module = AnsibleModule(
        argument_spec=<Resource>Args.argument_spec,
        mutually_exclusive=[["config", "running_config"]],
        required_if=[
            ["state", "merged", ["config"]],
            ["state", "replaced", ["config"]],
            ["state", "overridden", ["config"]],
            ["state", "rendered", ["config"]],
            ["state", "parsed", ["running_config"]],
        ],
        supports_check_mode=True,
    )
    result = <Resource>(module).execute_module()
    module.exit_json(**result)
```

### File 2: Argspec (`plugins/module_utils/network/ios/argspec/<resource>/<resource>.py`)
- Defines `argument_spec` dict matching the DOCUMENTATION options
- Auto-generated by `ansible.content_builder` — match structure to module docs
- All resource modules have `config` (list of dicts) + `running_config` (str) + `state` (choices)
- Standard states: `merged`, `replaced`, `overridden`, `deleted`, `rendered`, `gathered`, `parsed`
- Some modules also support `purged`

```python
class <Resource>Args(object):
    argument_spec = {
        "config": {
            "type": "list",
            "elements": "dict",
            "options": {
                # resource-specific options here
            },
        },
        "running_config": {"type": "str"},
        "state": {
            "choices": ["merged", "replaced", "overridden", "deleted",
                        "rendered", "gathered", "parsed"],
            "default": "merged",
            "type": "str",
        },
    }
```

### File 3: Config (`plugins/module_utils/network/ios/config/<resource>/<resource>.py`)
- Subclasses `ResourceModule` from `ansible.netcommon`
- Implements `execute_module()`, `generate_commands()`, and `_compare()`
- `self.parsers` lists the parser names from rm_templates that this module uses
- `generate_commands()` builds `wantd` and `haved` dicts keyed by resource identifier (e.g., interface name)
- `_compare()` calls `self.compare(parsers=self.parsers, want=want, have=have)` then inserts context command

```python
class <Resource>(ResourceModule):
    def __init__(self, module):
        super(<Resource>, self).__init__(
            empty_fact_val={},
            facts_module=Facts(module),
            module=module,
            resource="<resource_name>",
            tmplt=<Resource>Template(),
        )
        self.parsers = ["parser1", "parser2.nested", ...]

    def execute_module(self):
        if self.state not in ["parsed", "gathered"]:
            self.generate_commands()
            self.run_commands()
        return self.result

    def generate_commands(self):
        wantd = {entry["<key>"]: entry for entry in self.want}
        haved = {entry["<key>"]: entry for entry in self.have}
        # State-based logic: merged/replaced/overridden/deleted
        if self.state == "merged":
            wantd = dict_merge(haved, wantd)
        if self.state in ["deleted", "purged"]:
            haved = {k: v for k, v in haved.items() if k in wantd or not wantd}
            wantd = {}
        if self.state in ["overridden", "deleted"]:
            for k, have in haved.items():
                if k not in wantd:
                    self._compare(want={}, have=have)
        for k, want in wantd.items():
            self._compare(want=want, have=haved.pop(k, {}))

    def _compare(self, want, have):
        begin = len(self.commands)
        self.compare(parsers=self.parsers, want=want, have=have)
        if len(self.commands) != begin:
            self.commands.insert(begin, self._tmplt.render(want or have, "<context_cmd>", False))
```

### File 4: RM Templates (`plugins/module_utils/network/ios/rm_templates/<resource>.py`)
- Subclasses `NetworkTemplate` from `ansible.netcommon`
- Contains `PARSERS` list — each parser is a dict with:
  - `name`: dot-separated parser name (e.g., `"service_policy.input"`)
  - `getval`: compiled regex to parse CLI output lines
  - `setval`: Jinja2 template to generate CLI commands
  - `result`: dict mapping parsed groups to structured data
  - `shared`: (optional) True if this parser creates a new top-level entry

```python
class <Resource>Template(NetworkTemplate):
    def __init__(self, lines=None, module=None):
        super(<Resource>Template, self).__init__(lines=lines, tmplt=self, module=module)

    PARSERS = [
        {
            "name": "context_command",    # e.g., "interface"
            "getval": re.compile(r'''...regex...''', re.VERBOSE),
            "setval": "interface {{ name }}",
            "result": {
                "{{ name }}": {           # keyed result for top-level grouping
                    "name": "{{ name }}",
                },
            },
            "shared": True,               # marks this as creating new entry
        },
        {
            "name": "some_attribute",
            "getval": re.compile(r'''...regex...''', re.VERBOSE),
            "setval": "some-cli-command {{ value }}",
            "result": {
                "{{ name }}": {
                    "some_attribute": "{{ value }}",
                },
            },
        },
    ]
```

**Key regex patterns:**
- Context commands (interface, router bgp, etc.) use `^` anchor — they match at start of line
- Sub-commands use `\s+` prefix — they match indented lines within a context
- Named groups `(?P<name>...)` map directly to result template variables
- Use `re.VERBOSE` for readability

**Key setval patterns:**
- Simple: `"description {{ description }}"`
- Conditional: `"{{ ' clear' if snmp.ifindex.clear is defined else '' }}"`
- Negation: use `negate` capture group and check in result template

### File 5: Facts (`plugins/module_utils/network/ios/facts/<resource>/<resource>.py`)
- Collects running config from device, parses it using the template, and populates facts
- `get_<resource>_data()` runs the show command on the device
- `populate_facts()` uses the template parser, validates against argspec, and sets `ansible_network_resources.<resource>`

```python
class <Resource>Facts(object):
    def __init__(self, module):
        self._module = module
        self.argument_spec = <Resource>Args.argument_spec

    def get_<resource>_data(self, connection):
        return connection.get("show running-config | section ^<pattern>")

    def populate_facts(self, connection, ansible_facts, data=None):
        if not data:
            data = self.get_<resource>_data(connection)
        parser = <Resource>Template(lines=data.splitlines(), module=self._module)
        objs = sorted(list(parser.parse().values()), key=lambda k, sk="<key>": k[sk])
        ansible_facts["ansible_network_resources"].pop("<resource>", None)
        facts = {"<resource>": []}
        params = utils.remove_empties(
            parser.validate_config(self.argument_spec, {"config": objs}, redact=True),
        )
        facts["<resource>"] = params["config"]
        ansible_facts["ansible_network_resources"].update(facts)
        return ansible_facts
```

### Registration: Add to Facts Registry

After creating all 5 files, register the new resource in:
`plugins/module_utils/network/ios/facts/facts.py`

1. Add import for the new facts class
2. Add entry to `FACT_RESOURCE_SUBSETS` dict

### Action Plugin (`plugins/action/ios_<resource>.py`)

Every module needs a corresponding action plugin. It's boilerplate:

```python
from __future__ import absolute_import, division, print_function
__metaclass__ = type

from ansible.utils.display import Display
from ansible_collections.ansible.netcommon.plugins.action.network import (
    ActionModule as ActionNetworkModule,
)

display = Display()

class ActionModule(ActionNetworkModule):
    def run(self, tmp=None, task_vars=None):
        del tmp
        module_name = self._task.action.split(".")[-1]
        self._config_module = True if module_name in ["ios_config", "config"] else False
        persistent_connection = self._play_context.connection.split(".")[-1]
        if persistent_connection != "network_cli":
            return {
                "failed": True,
                "msg": "Connection type %s is not valid for this module"
                % self._play_context.connection,
            }
        return super(ActionModule, self).run(task_vars=task_vars)
```

Also add redirect entries in `meta/runtime.yml` under both `action:` and `modules:` sections:
```yaml
plugin_routing:
  action:
    <resource>:
      redirect: cisco.ios.ios_<resource>
  modules:
    <resource>:
      redirect: cisco.ios.ios_<resource>
```

## Creating a New Resource Module — Step by Step

### Step 1: Identify the IOS CLI structure
- Determine the `show` command that displays the resource config
- Identify the top-level context command (e.g., `interface`, `router bgp`, `vrf definition`)
- Map all sub-commands and their parameters
- See `ios_commands.md` for the full CLI reference

### Step 2: Create the 5 files + action plugin

For a new resource called `<resource>`:

1. **`plugins/modules/ios_<resource>.py`** — Module with DOCUMENTATION/EXAMPLES/RETURN + main()
2. **`plugins/module_utils/network/ios/argspec/<resource>/<resource>.py`** — ArgumentSpec
3. **`plugins/module_utils/network/ios/config/<resource>/<resource>.py`** — Config class
4. **`plugins/module_utils/network/ios/rm_templates/<resource>.py`** — Parser templates
5. **`plugins/module_utils/network/ios/facts/<resource>/<resource>.py`** — Facts class
6. **`plugins/action/ios_<resource>.py`** — Action plugin (boilerplate)

Create `__init__.py` in each new directory (argspec, config, facts).

### Step 3: Register in facts.py
Add import + FACT_RESOURCE_SUBSETS entry in `plugins/module_utils/network/ios/facts/facts.py`.

### Step 4: Add to meta/runtime.yml
Add action + module redirect entries.

### Step 5: Create tests

**Unit test** (`tests/unit/modules/network/ios/test_ios_<resource>.py`):
- Subclass `TestIosModule`
- Patch `get_resource_connection` and the facts `get_<resource>_data` method
- Provide CLI output via `self.execute_show_command.return_value = dedent("...")`
- Test all states: merged, replaced, overridden, deleted, gathered, parsed, rendered
- Assert `result["commands"]` matches expected commands
- Assert `result["changed"]` is True/False as expected
- Test idempotency: run same config twice, second should have `changed == False`

**Molecule test** (`extensions/molecule/<resource>/`):
- `molecule.yml` — defines platforms per state (gathered, merged, replaced, overridden, deleted, rtt)
- `converge.yml` — test playbook covering all states
- `vars.yml` — expected results (commands, before, after)
- CISSHGO fixtures in `extensions/molecule/cisshgo_fixtures/`:
  - Transcripts: `transcripts/ios_<resource>/` with show command outputs
  - Transcript map: add entries to `transcript_map.yaml`
  - Ansible inventory: `inventories/ansible/<resource>.yaml`
  - CISSHGO host inventory: `inventories/cisshgo/<resource>.yaml`

### Step 6: Add changelog fragment
Create `changelogs/fragments/<resource>.yaml`:
```yaml
---
minor_changes:
  - ios_<resource> - Added new resource module for <description>.
```

## Key Dependencies

- **`ansible.netcommon`** (>= 8.5.2) — Base classes: `ResourceModule`, `NetworkTemplate`, `FactsBase`
- **`ansible.utils`** — Utility filters and lookup plugins
- **Python 3.9+** — Required Python version
- **CISSHGO** — SSH simulator for Molecule tests (Go binary)

### Important Base Classes

From `ansible.netcommon`:
- `ResourceModule` (`rm_base.resource_module`) — Base for all config classes
  - Provides: `self.want`, `self.have`, `self.state`, `self.commands`, `self.result`
  - Methods: `compare()`, `addcmd()`, `run_commands()`, `get_parser()`
- `NetworkTemplate` (`rm_base.network_template`) — Base for all parser templates
  - Provides: `parse()`, `render()`, `validate_config()`
  - `parse()` iterates lines, matches against PARSERS, builds structured data
  - `render()` generates CLI commands from structured data using setval templates
- `FactsBase` (`facts.facts`) — Base for the facts registry class

## Coding Conventions

- All files start with the copyright header and `from __future__ import absolute_import, division, print_function`
- Use `__metaclass__ = type` after imports
- Naming: `ios_<resource>` for modules, `<Resource>` for classes (CamelCase)
- Parsers use `re.VERBOSE` for readability
- Templates use `# fmt: off` / `# fmt: on` around PARSERS list to prevent auto-formatting
- Use `normalize_interface()` from `utils.py` when working with interface names
- CLI commands use hyphens (`service-policy`), Python attributes use underscores (`service_policy`)
- Boolean config options in argspec use `type: bool`; in parsers, convert with `"{{ not not varname }}"`
- Action plugin is the same boilerplate for every module — copy from any existing one
- Changelog fragments go in `changelogs/fragments/` as YAML files
