*********************************
cisco.ios.ios_flow_monitor_global
*********************************

**Resource module to configure Flexible NetFlow on Cisco IOS XE.**


Version added: 11.7.0

.. contents::
   :local:
   :depth: 1


Synopsis
--------
- This module manages the Flexible NetFlow global configuration on Cisco IOS XE devices.
- It manages flow records, flow exporters, samplers, and flow monitors as named entities.

Notes
-----

.. note::
   - Tested against Cisco IOS XE.
   - This module works with connection ``network_cli``. See https://docs.ansible.com/ansible/latest/network/user_guide/platform_ios.html
   - The module examples use callback plugin (stdout_callback = yaml) to generate task output in yaml format.
   - Some options (``cache type permanent``, ``transport tcp``) are only supported on router platforms.
   - Catalyst 9300 accepts ``cache entries`` without an error but does not keep it in the running configuration. A monitor that sets ``cache.entries`` is therefore reported as changed on every run on that platform, so leave it out there. The ``cache`` timeouts are kept.
   - The platforms accept different ``collect`` options. The module does not check the platform, the device rejects an option it does not support when the commands are applied. Commands sent before the rejected one stay applied.
   - Tested on a Catalyst 9300 (IOS XE 17.12.4 and 17.18.4) and a Catalyst 9600 (C9606R, IOS XE 17.12.5 and 17.12.6), all with Network Advantage and DNA Advantage licenses. The license does not change which options are accepted, and IOS XE 17.12.5 and 17.12.6 gave the same results.
   - Catalyst 9600 accepts ``counter_bytes`` and ``counter_packets`` (``collect counter bytes``, ``collect counter packets``) and ``timestamp_sys_uptime_first`` and ``timestamp_sys_uptime_last``. Existing flow records on these devices use them.
   - Catalyst 9300 rejects ``counter_bytes`` and ``counter_packets`` with ``% Incomplete command``, and rejects ``timestamp_sys_uptime_first`` and ``timestamp_sys_uptime_last`` as invalid input. Use ``counter_bytes_long``, ``counter_bytes_layer2_long``, ``counter_packets_long``, ``timestamp_absolute_first`` and ``timestamp_absolute_last`` there.
   - Both Catalyst 9300 and Catalyst 9600 reject ``counter_bytes_layer2`` (it needs ``long``, use ``counter_bytes_layer2_long``), ``routing_source_as`` and ``routing_destination_as`` without qualifier, and the ``routing_source_as_peer`` and ``routing_destination_as_peer`` variants, all with ``% Incomplete command``. These options are for other platforms.
   - Accepted on both Catalyst 9300 and Catalyst 9600, so these are the safe choice on both, ``counter_bytes_long``, ``counter_bytes_layer2_long``, ``counter_packets_long``, ``timestamp_absolute_first``, ``timestamp_absolute_last``, ``routing_source_as_4octet``, ``routing_destination_as_4octet``, ``routing_next_hop_ipv4``, ``transport_tcp_flags``, ``interface_input`` and ``interface_output``.
   - IOS XE (Catalyst 9300 and 9600) does not show values that are the default in the running configuration, for example ``cache timeout inactive 15``, ``cache timeout active 1800`` and the exporter ``export-protocol netflow-v9``, ``template data timeout 600``, ``ttl 255`` and ``dscp 0``. The module treats these as equal to an unset value, so specifying them does not cause a change on every run.
   - IOS XE ignores changes to a flow record, without reporting an error, while a flow monitor that uses it exists. To change a record, delete the flow monitors using it first, or use a new record name.



Examples
--------

.. code-block:: yaml

    # Using state: merged

    # Before state:
    # router# show running-config | section ^(flow|sampler)
    # (empty)

    - name: Configure Flexible NetFlow (Catalyst 9600 and routers, see the notes for Catalyst 9300)
      cisco.ios.ios_flow_monitor_global:
        config:
          records:
            - name: FLOW_RECORD_IPV4
              match:
                ipv4_tos: true
                ipv4_protocol: true
                ipv4_source_address: true
                ipv4_destination_address: true
                transport_source_port: true
                transport_destination_port: true
                flow_direction: true
                interface_output: true
              collect:
                routing_source_as_4octet: true
                routing_destination_as_4octet: true
                routing_next_hop_ipv4: true
                transport_tcp_flags: true
                counter_bytes: true
                counter_packets: true
                timestamp_sys_uptime_first: true
                timestamp_sys_uptime_last: true
                interface_input: true
          exporters:
            - name: FLOW_EXPORTER_1
              destination: 192.0.2.1
              vrf: MGMT
              source: Loopback0
              transport:
                protocol: udp
                port: 2055
              options:
                sampler_table_timeout: 10
          samplers:
            - name: FLOW_SAMPLER
              mode: random
              window_size: 1000
          monitors:
            - name: FLOW_MONITOR_OUT
              exporters:
                - FLOW_EXPORTER_1
              cache:
                timeout_inactive: 10
                timeout_active: 60
              record: FLOW_RECORD_IPV4
        state: merged

    # Commands fired:
    # flow record FLOW_RECORD_IPV4
    #  match ipv4 tos
    #  match ipv4 protocol
    #  match ipv4 source address
    #  match ipv4 destination address
    #  match transport source-port
    #  match transport destination-port
    #  match flow direction
    #  match interface output
    #  collect routing source as 4-octet
    #  collect routing destination as 4-octet
    #  collect routing next-hop address ipv4
    #  collect transport tcp flags
    #  collect counter bytes
    #  collect counter packets
    #  collect timestamp sys-uptime first
    #  collect timestamp sys-uptime last
    #  collect interface input
    # flow exporter FLOW_EXPORTER_1
    #  destination 192.0.2.1 vrf MGMT
    #  source Loopback0
    #  transport udp 2055
    #  option sampler-table timeout 10
    # sampler FLOW_SAMPLER
    #  mode random 1 out-of 1000
    # flow monitor FLOW_MONITOR_OUT
    #  exporter FLOW_EXPORTER_1
    #  cache timeout inactive 10
    #  cache timeout active 60
    #  record FLOW_RECORD_IPV4

    # Using state: merged — Catalyst 9300 flow record
    #
    # Catalyst 9300 rejects the counter_bytes, counter_packets and timestamp_sys_uptime options
    # used in the first example, it needs the long counters and absolute timestamps.

    - name: Configure a flow record on a Catalyst 9300
      cisco.ios.ios_flow_monitor_global:
        config:

                flow_direction: true

                routing_source_as_4octet: true
                routing_destination_as_4octet: true
                routing_next_hop_ipv4: true
                transport_tcp_flags: true
                counter_bytes_layer2_long: true
                counter_packets_long: true

                timestamp_absolute_last: true
                interface_input: true
        state: merged

    # Commands fired:
    # flow record FLOW_RECORD_IPV4
    #  match ipv4 tos
    #  match ipv4 protocol
    #  match ipv4 source address
    #  match ipv4 destination address
    #  match transport source-port
    #  match transport destination-port
    #  match flow direction
    #  match interface output
    #  collect routing source as 4-octet
    #  collect routing destination as 4-octet
    #  collect routing next-hop address ipv4
    #  collect transport tcp flags
    #  collect counter bytes layer2 long
    #  collect counter packets long
    #  collect timestamp absolute first
    #  collect timestamp absolute last
    #  collect interface input

    # Using state: merged — dual exporter (two collectors)

    - name: Configure flow monitor with dual exporters
      cisco.ios.ios_flow_monitor_global:
        config:
          exporters:
            - name: FLOW_EXPORTER_1
              destination: 192.0.2.1
              vrf: MGMT
              source: Loopback0
              transport:
                protocol: udp
                port: 9996
              options:
                sampler_table_timeout: 2000
                template_data_timeout: 10000
            - name: FLOW_EXPORTER_2
              destination: 192.0.2.2
              vrf: MGMT
              source: Loopback0
              transport:
                protocol: udp
                port: 9996

    - name: Remove all flow monitor configuration
      cisco.ios.ios_flow_monitor_global:
        state: deleted

    # Using state: gathered

    - name: Gather existing flow monitor configuration
      cisco.ios.ios_flow_monitor_global:
        state: gathered

    # Using state: rendered

    - name: Render commands without connecting to device
      cisco.ios.ios_flow_monitor_global:
        config:
          samplers:
            - name: FLOW_SAMPLER
              mode: random
              window_size: 1000
        state: rendered

    # Using state: parsed

    - name: Parse device config into structured data
      cisco.ios.ios_flow_monitor_global:
        running_config: |
          flow record FLOW_RECORD_IPV4
           match ipv4 source address
           match ipv4 destination address
           collect counter bytes
           collect counter packets
          sampler FLOW_SAMPLER
           mode random 1 out-of 1000
          flow monitor FLOW_MONITOR_OUT
           record FLOW_RECORD_IPV4
        state: parsed
